# Calling and texting budgets

Admin workspace: `/crm-communications.html` on sales.turnlypros.com. Only active CRM administrators can read account spending, modify settings, pause outreach, or change per-member allowances. Service-role-only tables and functions enforce the budget; no browser-supplied amount is trusted.

Initial defaults: $10/day, $100/month shared; same ceilings for each member within the shared pool; 20-minute call maximum. UTC periods align with Twilio usage records. Admins can set a $0 limit or pause everyone, a channel, or an individual. Raising limits is an audited admin override. In-flight calls finish within their reserved time; pause does not terminate ongoing calls.

Every application SMS sender (CRM, referral portal, turn-request notification) uses the same reservation function. Email is outside this budget. Calls require a reservation at preparation and again at TwiML consumption. A shared transaction advisory lock serializes reservations, settings, expiration and settlement. Text segments account for GSM extension characters and Unicode UTF-16 length. Both calling and texting restrict recipients to US numbers.

Budget amounts are conservative estimates: default 5 cents/minute for combined browser and telephone call legs, 5 cents/SMS segment. The database enforces minimum rates of 5 cents; administrators can raise rates. A call reserves its maximum duration plus two overhead minutes. Terminal callbacks settle to rounded minutes plus connection overhead. Unknown SMS outcomes retain the reservation; they are never automatically refunded or re-sent. Prepared calls without a Twilio parent expire after three minutes under the same lock that consumes calls. Missed terminal callbacks are reconciled against Twilio.

The five-minute `/api/communication-budget` cron uses existing `CRON_SECRET`, with an admin manual sync. It reads account usage, balance and reported per-communication prices. Reported charges can lag and may omit fees. Budget enforcement takes the higher of the local conservative settled usage and Twilio account usage, then adds all outstanding reservations. Account usage includes number rental/other services as a safety floor. This is an application outreach control, not an exact Twilio billing cap: inbound traffic, external applications, fees and delayed reporting cannot be blocked here.

Admin overview notifications are deduplicated by UTC period at 50%, 80%, 100% including reservations. Settings changes are audited. Recent communication history is limited to 100 displayed records, while budget totals include all applicable records. Reconciliation prioritizes up to 100 outstanding reservations plus the latest 100 records per run. Uncertain SMS reservations require provider investigation; there is intentionally no blind release button.

Validation: PGlite executes actual migrations, tests mixed-channel and burst reservations, monthly caps, per-rep pause/allowances, admin authorization, RLS denial, duplicate prevention, callback idempotency, stale call expiration and session compatibility. Referral send integration tests verify the new common SMS path without making live sends.
