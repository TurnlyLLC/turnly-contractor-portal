Connect residential card booking

Until setup is completed, the customer flow saves booking requests with referral attribution. It never claims a reservation, saves a card, or charges a customer without Stripe.

1. Stripe keys

  1. Open your Stripe account and complete its business verification.
  2. In Stripe API keys, select the testing sandbox first. Copy its secret key.
  3. In Vercel → turnly-contractor-portal → Settings → Environment Variables, save STRIPE_SECRET_KEY in Production as a sensitive value. Do not put keys in source files, browser code, or chat.

2. Signed payment updates

  1. In Stripe Workbench → Webhooks, create a snapshot event destination for your account at https://portal.turnlypros.com/api/residential-webhook.
  2. Select checkout.session.completed, payment_intent.succeeded, payment_intent.payment_failed, payment_intent.processing, payment_intent.canceled, charge.refunded, charge.dispute.created, and charge.dispute.closed.
  3. Save the endpoint’s signing secret in Vercel as the sensitive STRIPE_WEBHOOK_SECRET.

3. Scheduled service-day charges

  1. Generate a random secret of at least 32 bytes and save it as sensitive CRON_SECRET in Vercel.
  2. The project’s hourly cron calls /api/residential-charge. Vercel sends the cron secret automatically. Hourly cron requires a Vercel plan supporting that frequency.
  3. Set RESIDENTIAL_PAYMENTS_ENABLED=true only after keys, webhook, and cron are configured. Redeploy production to apply the settings.
  4. Test a booking with a Stripe test card. Check that Checkout uses setup mode and collects no service payment. Verify the booking becomes Scheduled, then use a separate test booking’s service date to test the morning charge, failed-card handling, duplicate cron calls, and refunds.
  5. After tests pass, replace both Stripe secrets with the live account’s key and live webhook secret, then redeploy. Test and live secrets must match.

Charges run at 6am Eastern on the service date, or at the start of an earlier arrival window. The hourly worker catches a due visit on that date, uses one durable idempotency key, and stops ambiguous retries before Stripe’s idempotency window expires. Check the admin payment statuses daily. Failed cards require customer follow-up; the system does not silently charge a new card.

4. Property data

The customer page uses RentCast’s property-record endpoint to look up bedrooms, bathrooms, and living-area square footage from a full street address. Create an API key in the RentCast API dashboard. Activate an API subscription in that dashboard; creating a key alone does not activate property access. Save it as sensitive RENTCAST_API_KEY in Vercel Production and redeploy. Restrict the key to the property-record endpoint and set an account usage limit. Customers can correct a match or enter details manually if the provider is unavailable or the property cannot be matched.

Pricing and operations

The initial standard clean is $0.13/sq ft, minimum $175. Deep, move-in/out, and listing/staging are $0.21/sq ft, minimum $175. Following maintenance visits: monthly $0.12 / $165 minimum; bi-weekly $0.11 / $150; weekly $0.10 / $140. This flow books the first visit. Arrange recurring visits separately. Homes over 3,000 sq ft require a custom review and do not proceed to automatic card booking.

The full rate is calculated on the server. Profile and property addresses are stored separately. Agent credit is preserved on each booking, and the 10% bonus is earned only for the first completed, fully paid clean. Refunds or disputes remove unpaid bonus eligibility. Marking a bonus paid records your payout; it does not transfer funds.
